# План второго задания до обучения и тестовой оценки

Это отдельный проект: GPT-2 по ID треков, reward model и RL на Yambda-50M.
Выбраны 1000 слушателей равномерно из 9238 пользователей файла listens, seed 314.
Сохраняются все предоставленные listening events этих пользователей, включая
органические события, пропуски и повторы. Другие типы событий не используются.
Источник фиксируется commit и SHA-256 в data/SOURCE_MANIFEST.json.

## Доступность данных

Три последние последовательные недели: validation, confirmation, test.
Всё более раннее - train. Границы общие для всех пользователей. Треки словаря
выбираются только по train; остальные сохраняются в истории как UNK. Полная
история хранится, контекст модели ограничен 64 токенами. Ранжирование проводится
по всему фиксированному словарю из 16384 треков. OOV-цели получают нулевой вклад
в общую метрику; отдельно выводится условная метрика и покрытие словаря.

В Yambda время выражено в секундах от начала наблюдений, округлённых до 5 секунд
(формула в статье о датасете). Внутри одинакового timestamp порядок неизвестен.
Контекст каждого оценочного запроса содержит только события с меньшим временем.
Для packed LM loss используются только однозначные цели без других событий
в той же временной группе. Прошлые группы упорядочиваются канонически по ID.
Это технический порядок внутри уже прошедшего блока, не утверждение о реальной
последовательности. Цели - recommendation-driven events; organic events входят
в контекст. Контроли не сэмплируются: softmax и ranking по всему словарю.

## Модели

GPT2LMHeadModel обучается с нуля: токены - ID треков, 2 decoder layers, 4 heads,
width 96/128 выбирается на validation. Другие настройки в configs/main.json.
Три seed 42,43,44. SFT checkpoint выбирается по validation NDCG@10. Референс
замораживается. Параметры, tokenizer/vocabulary и окна одинаковы для всех
сравниваемых вариантов внутри seed.

Оптимизируемая reward model оценивает clipped played_ratio_pct/100, а вторая
голова - наблюдаемый возврат в окно (t+24h,t+48h]. Это два CatBoost предиктора
по строго прошлой истории ID и известным к train метаданным кандидата. Текущий
played_ratio и будущее поведение отсутствуют во входах. Признаки профиля используют
замороженные embeddings базового GPT-2; в RM нет обращения к тестовым событиям.
Reward label обучающего примера допускается лишь при полностью наблюдаемом
горизонте внутри его split. Для current completion дополнительно учитывается
консервативное время окончания прослушивания.

Reward optimizer обучается на случайной половине пользователей train; отдельный
аудитор ExtraTrees обучается на другой половине и числовых признаках. Это
диагностика коррелированных ошибок и изменения предсказанной награды. Аудитор
также является моделью; его score не является наблюдаемой контрфактической истиной.
Качество обеих моделей проверяется на реальных отложенных logged actions.

## RL и контроли

On-policy REINFORCE с leave-one-out baseline внутри группы из четырёх траекторий.
Horizon 5, gamma 0.9, sample temperature 1. RL применяется в модели среды,
заданной reward model: взаимодействия с реальными пользователями отсутствуют.
KL к замороженной SFT-политике включается как -beta*log(pi/pi_ref) в return-to-go.
Один gradient update на текущие on-policy rollout, без повторного использования
старых траекторий. При RL dropout выключен и при sampling, и при вычислении
log probability. Gradient остаётся включённым для policy update.

Варианты заранее заданы: completion без KL; completion с beta 0.05/0.2;
ожидаемые секунды min(duration,600)*completion/300; balanced reward; bandit
контроль с пятью независимыми рекомендациями из одного фиксированного контекста.
В bandit matched число actions/updates, но не контекстные переходы. Balanced:
0.7*completion + 0.2*return_proxy + 0.1*novelty - 0.25*recent_repeat
- 0.1*RM_standard_deviation; дополнительный CE coefficient 0.05.

Continued-CE начинает с той же SFT и получает те же 300 optimizer updates и
префиксы. Это контроль дополнительного обучения. Число optimizer updates и
семплированных RL actions фиксировано; фактическое wall time и число CE targets
измеряются, равенство FLOPs/времени не заявляется.

Checkpoint каждого RL варианта выбирается по собственной ожидаемой validation
награде; balanced использует порог 0.95*SFT validation NDCG. Если порог не
выполнен ни в одном checkpoint, выбирается checkpoint с наибольшим NDCG и
неисполнение ограничения явно отмечается. Continued-CE - по validation NDCG.

## Итоговое сравнение

Первичное фиксированное сравнение: balanced RL против continued-CE. Frozen SFT
и остальные варианты - необходимые дополнительные сравнения. Три отдельных
seed, mean и SD. Bootstrap по пользователям над средними per-query метриками
трёх seed; это не ансамбль вероятностей и не полная оценка неопределённости seed.

Recall/NDCG@5/10/20, полное и условное на словаре покрытие, ожидаемый completion
по оптимизируемой и аудиторской RM, duration, repeat, diversity/coverage,
entropy/Gini и сходство выдач разных пользователей. Reward model оценивается
через MAE/RMSE/R2 и метрики return proxy на logged heldout events, с контролями
среднего и train item mean. Дополнительно анализируются calibration/high-score
срезы и расхождение моделей; различие двух RM не доказывает reward hacking само
по себе, но выявляет чувствительность к выбору surrogate.

Для 5-step rollout сравниваются teacher-forced реальные префиксы, слепое
добавление рекомендаций, фиксированный контекст и модельное принятие действия.
Это stress test переходов контекста. Сгенерированная рекомендация не объявляется
состоявшимся действием пользователя. Model-based reward не является доказательством
роста удовлетворённости/retention. Нет истинных logging propensities, поэтому
не заявляется несмещённая off-policy/causal оценка. Источник сам отбирал активных
пользователей с возвращением в последнем месяце: это ограничение churn-выводов.

Рекомендация на confirmation: среди RL вариантов, прошедших порог 0.95 от
continued-CE NDCG, выбрать максимум ожидаемого completion основной RM; иначе
оставить continued-CE. Фиксированное первичное сравнение от этого не меняется.
Выбор и SHA моделей сохраняются до чтения test модулем оценки. Все результаты,
включая провалы и невыполнение порога, входят в отчёт. Позитивный RL-эффект
не является условием успеха исследования.

## Связь с двумя указанными статьями

Petrov & Macdonald, 2024: Next-K и RL для целей всего списка; их teacher-student
pretraining/PPO не воспроизводятся буквально. Здесь pretraining соответствует
заданию - next-item GPT-2 - и используется REINFORCE.
https://arxiv.org/abs/2403.04875

Matveev et al., 2026: session-level REINFORCE, feedback model, многошаговая
оценка и ограничения model-based return. Их two-tower/off-policy correction и
результаты на 5B не переносятся в эту небольшую модель. Здесь on-policy выборка
в surrogate среде и явный контроль замены реального состояния сгенерированным.
https://arxiv.org/abs/2607.02818

Описание единиц времени и исходного отбора пользователей:
https://arxiv.org/abs/2505.22238

Разведочный аудит данных до первого обучения: словарь 2048 покрывал 26.6% train и был заменён на 16384 (64.9% train). Проверялось также покрытие отложенных target ID; recommendation/reward model metrics ещё не вычислялись. Размер выбран по train support и CPU-микробенчмарку; оценка не является полностью слепой к составу отложенных объектов. Версия 2048 сохранена только как design audit, без моделей или сравнительных результатов.
Ожидаемые model-based награды оцениваются Monte Carlo по 32 действиям на запрос, с общими uniform random numbers для сравниваемых моделей; ranking по каталогу точный.
